## Linux real-time scheduling and DDS Deadline

| Claim in article | Source actually read and relevant section | Version/date | Status |
|---|---|---|---|
| Fast DDS Deadline describes expected maximum period for application supply at Writer and sample arrival at Reader; offered/requested compatibility has a direction. | eProsima [Fast DDS standard QoS policies](https://fast-dds.docs.eprosima.com/en/2.x/fastdds/dds_layer/core/policy/standardQosPolicies.html), section `DeadlineQosPolicy` and “Compatibility Rule”. Opened text directly. | Documentation page identified as Fast DDS 2.14.7 on 2026-10-13; project binary version is 2.11.2 | 확인, version boundary preserved |
| SCHED_DEADLINE uses per-task runtime, relative deadline, and period; a formal schedulability guarantee depends on task assumptions and admission test. | Linux kernel [Deadline Task Scheduling](https://docs.kernel.org/scheduler/sched-deadline.html), parameter overview, task constraints/relationship to SCHED_DEADLINE parameters. Opened text directly. | Linux kernel docs current page read 2026-10-13 | 확인 |
| For the described model, Linux docs relate runtime to WCET, deadline to D and period to P; this is conditional, not a blanket product guarantee. | Same kernel source, section “Relationship with SCHED_DEADLINE Parameters”, explicit bullet premises and admission-control statement. | Current page read 2026-10-13 | 확인 |
| SCHED_DEADLINE `sched_yield()` gives up remaining runtime and throttles until replenishment; generic yield does not mean “sleep one period”. | Linux kernel [sched-deadline](https://docs.kernel.org/scheduler/sched-deadline.html), §4.4; Linux man-pages [`sched_yield(2)`](https://man7.org/linux/man-pages/man2/sched_yield.2.html). | Current docs read 2026-10-13 | 확인 |
| `sched_setattr()` targets a thread; pthread execution scheduling is not an application callback or release timer. | Linux man-pages [`sched_setattr(2)`](https://man7.org/linux/man-pages/man2/sched_setattr.2.html) and [`pthreads(7)`](https://man7.org/linux/man-pages/man7/pthreads.7.html), target PID/TID and NPTL model. | Current docs read 2026-10-13 | 확인 |
| `clock_nanosleep()` and `timerfd` can implement app-level release waits; wakeup does not itself prove on-time execution. | Linux man-pages [`clock_nanosleep(2)`](https://man7.org/linux/man-pages/man2/clock_nanosleep.2.html), [`timerfd_create(2)`](https://man7.org/linux/man-pages/man2/timerfd_create.2.html). | Current docs read 2026-10-13 | 확인 + 추론 |
| DDS write/callback/device completion are distinct end-to-end timing boundaries from CPU scheduling and DDS Deadline. | Derived from Fast DDS Deadline definition and Linux scheduler model; aligned with canonical note `주기 DDS 발행: 일반 스케줄러와 SCHED_DEADLINE 비교`. | Research synthesis; note dated 2026-10-10 and updated 2026-10-13 | 추론 |
| Project uses relative sleeps (simulator 100ms, controller 50ms), not a measured SCHED_DEADLINE deployment. | Canonical notes `세 프로세스와 상태 머신 설계`, `주기 DDS 발행: 일반 스케줄러와 SCHED_DEADLINE 비교`, and `구현 시험 결과`. | Actual run/test record 2026-10-09 | 확인 |
